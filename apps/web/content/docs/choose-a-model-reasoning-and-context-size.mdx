Click the model picker next to the composer's **+** button to set the agent, model, reasoning level and speed.

## Pick a model and reasoning level

<Tabs items={["Desktop", "CLI"]}>
<Tab value="Desktop">

1. Click the model picker, or use its [keyboard shortcut](/docs/keyboard-shortcuts).
2. Choose the agent from the icons along the top, then a model under **Model**.
3. Choose a level under **Reasoning**.
4. For a faster speed, turn on **Fast mode** or pick one under **Speed**.

</Tab>
<Tab value="CLI">

```sh
bb provider models claude-code
bb thread spawn --provider claude-code --model claude-opus-5-5 --reasoning-level high "Review the open PR"
```

`--service-tier fast` picks a faster speed. `--option <option=value>` sets a model option such as Codex's Daybreak.

</Tab>
</Tabs>

| Agent | Reasoning levels (each model may offer fewer) |
| --- | --- |
| Claude Code | Low, Medium, High, Extra High, Ultracode, Max |
| Codex | None, Low, Medium, High, Extra High, Max, Ultra |
| Pi | None, Low, Medium, High, Extra High, Max |
| ACP agents | What the agent reports |

Faster speeds cost more. **Allow faster service tiers** in **Settings → Providers** turns them off for every agent, including queued messages and automations.

## Change the model in a running thread

Pick a new model or level in the thread's composer; it applies from the next message. To switch agent, choose **Handoff to new thread** in the same menu.

| Command | Effect |
| --- | --- |
| `bb thread tell <id> --model <model> "message"` | Uses the model for one message |
| `bb thread update <id> --model <model>` | Keeps it for the following turns |

## Set defaults for a project

There is no default model setting. New threads in a project reuse the agent, model, reasoning level, permission mode and speed of your last thread there from the app.

- **Default agent:** check **Default** in the agent's **⋯** menu in **Settings → Providers**. It applies where you haven't picked one yet.
- **Child threads** start with their parent's model and reasoning level when they use the same agent.
- **CLI:** `bb thread spawn` without `--provider` or `--model` uses the project's choice, then the agent's default.

## Get 1M context

The context window belongs to the model and your account, not to bb.

- **Claude Code** decides which models get a 1M-token window for your account; a separate 1M version ends in **(1M)**.
- **Disable 1M context** in **Settings → Plugins → Claude Code provider** turns it off.
- Threads routed through the [Account Pooler](/docs/use-several-accounts) keep the 1M window.

Hover the composer's ring for tokens used out of the window; it turns amber at 75% and red at 90%. `/compact` or `bb thread compact <id>` summarizes a full thread, on agents that support it.

## If a model is missing

The list comes from the agent on the thread's machine, reread in the background and when a machine connects.

1. Update the agent there. New models usually need a newer version.
2. Check what it reports: `bb provider models <provider-id> --machine <machine>`.
3. If it couldn't load models, the agent isn't installed or signed in there. See [Claude Code](/docs/claude-code), [Codex](/docs/codex), [Pi](/docs/pi) or [ACP agents](/docs/add-acp-agents).

For a model ID an agent accepts but doesn't list, add it to `customModels`; see [Run local models](/docs/add-acp-agents#run-local-models).

## Check it worked

The picker shows your choice, and the next reply uses it.
