bb has no agent login of its own. Sign in to each agent's CLI on the machine that runs your threads, as you would in a terminal, and bb uses that sign-in and your existing config.

## Agents bb knows

Settings calls agents **Providers**.

| Agent | Command bb runs | Sign in with | bb can install it |
| --- | --- | --- | --- |
| Claude Code | `claude` | `claude auth login` | Yes |
| Codex | `codex` | `codex login` | Yes |
| Pi | `pi` | `pi` | Yes |
| Cursor | `cursor-agent acp` | `cursor-agent login` | Yes |
| opencode | `opencode acp` | `opencode auth login` | No |
| omp | `omp acp` | `omp login` | No |
| Grok Build | `grok agent stdio` | `grok login` | No |
| Hermes Agent | `hermes acp` | `hermes login` | No |

Cursor is always listed; the last four appear only on machines where their command is installed. For any other agent, see Add Cursor, opencode and other ACP agents.

## Sign in to an agent

<Tabs items={["Desktop", "Terminal"]}>
<Tab value="Desktop">

1. Open the setup guide. It opens on first run; later, choose **Show setup guide** in **Settings → General**.
2. On **Connect a coding agent**, find your agent. **Ready** means it's signed in.
3. If it's **Not installed**, choose **Install**, or install it yourself and choose **Check again**.
4. Choose **Sign in**, then **Open sign-in page**. Paste the code back if the agent gives you one.
5. When the agent shows **Ready**, choose **Continue**.

<Tab value="Terminal">

Run the sign-in command from the table on the machine that runs your threads:

```bash
claude auth login
codex login
```

Over SSH, `codex login --device-auth` signs in with a one-time code instead of a browser. You don't need to restart bb.

## How bb finds your agents

| What | Where bb looks |
| --- | --- |
| The command | The PATH from your login shell, plus common folders such as `~/.local/bin`, `/opt/homebrew/bin` and `/usr/local/bin`. An agent installed while bb runs is found the next time bb looks. |
| Claude Code sign-in | The macOS Keychain, or `~/.claude/.credentials.json` |
| Codex sign-in | `~/.codex/auth.json`, or `auth.json` in `CODEX_HOME` if you set it |
| Pi sign-in | Signed in when Pi can list at least one model |
| Cursor sign-in | The sign-in saved by `cursor-agent login` |
| Other ACP agents | Ready once their command is installed |
| Config | The agent's usual files: Claude Code keeps its `CLAUDE.md`, settings and MCP servers; Codex keeps its `AGENTS.md` and skills |

Each machine has its own agents and sign-ins. When you add a machine, sign in to your agents there too.

## Choose which agents bb shows

In **Settings → Providers**, each enabled agent appears in the provider picker for new threads.

- **⋯ → Disable** hides an agent; **Enable** brings it back.
- **⋯ → Default** makes it your default agent.
- Drag agents to reorder the picker.

```bash
bb provider list
bb provider enable codex
bb provider disable acp-cursor
```

## Check it worked

- The setup guide shows **Ready** next to your agent, or `bb provider list --all` shows it as **Enabled**.
- In a new thread, pick the agent in the provider picker; the model picker lists its models.

## Related troubleshooting

- An agent won't sign in or can't be found
- A model is missing from the model picker
